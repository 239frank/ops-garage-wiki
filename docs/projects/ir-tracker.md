# Incident Response Tracker

## Purpose

A lightweight incident response tracker designed for SOC-style workflows.

## Problem

Incident response work can become scattered across chats, spreadsheets, tickets, and memory. Smaller teams need a simple way to track incidents, actions, status, ownership, notes, and follow-up tasks without overbuilding the process.

## Approach

The goal is to keep the workflow simple:

- Open an incident
- Assign ownership
- Track status
- Capture actions taken
- Document artifacts and notes
- Close with lessons learned

## Tools Used

- Web application prototype
- Docker / self-hosted deployment
- Unraid lab environment
- Incident response workflow design
- Future automation hooks

## Outcome

The project creates a practical way to demonstrate incident response process thinking, lightweight tooling, and technician-friendly workflow design.

## Lessons Learned

- Keep the workflow simple enough that a technician would actually use it.
- Do not overbuild dashboards before the core incident process works.
- A useful MVP is better than a complicated tool nobody wants to maintain.
